### Shims for effects the imported content calls that TNORA does not have.
###
### The policy-effectiveness family is gone. TNORA has no effectiveness track -
### it moves laws directly, with tno_<policy>_improve and tno_<policy>_worsen -
### so those 354 definitions did nothing, and every call to them has been
### rewritten into a real law change.
###
### What is left below is the families that have no TNORA equivalent at all:
### administrative efficiency, the five funding sliders, and the alert wrappers.

### Policy-effectiveness ladders.
### Shim layer: TNORA has no policy-effectiveness system, but a great deal of
### imported content calls these. Each entry banks its magnitude on a namespaced
### accumulator so nothing is silently lost if the system is built later.
### Pattern and magnitudes mirror TNO_SocDev_scripted_effects.txt (low/med/high = 1/2/3).

### TNO alert helpers. Upstream drives a notification widget TNORA does not have;
### these keep the call sites valid and leave a country flag behind as the hook.

add_TNO_alert = {
	if = {
		limit = { NOT = { has_country_flag = TNO_alert_active } }
		set_country_flag = TNO_alert_active
	}
}

add_TNO_alert_unless_exists = {
	add_TNO_alert = yes
}

remove_TNO_alert = {
	clr_country_flag = TNO_alert_active
}

remove_TNO_alert_data = {
	remove_TNO_alert = yes
}
